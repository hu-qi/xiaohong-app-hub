## **注意：ESP32-P4 的 v1.x 与 v3.x 版本的区别**

ESP32-P4 如果是 **v1.x** 版本（小鸿SE主板上**带有 “东开鸿” 字样**） ，需要用烧录工具 (**v3.9.10** 版本以上)烧录 "**20260804-ESP32-P4-v1.x**" 目录下的固件；

ESP32-P4 如果是 **v3.x** 版本（小鸿SE主板上**不带 “东开鸿” 字样**） ，需要用烧录工具 (**v3.9.11** 版本以上)烧录 "**20260804-ESP32-P4-v3x**" 目录下的固件；

ESP32的 **v3.9.11** 版本烧录工具的下载路径为：https://dl.espressif.com/public/flash_download_tool.zip

两个版本的固件，差异点在于：

编译 **v1.x** 版本固件时，P4 代码根目录下的 sdkconfig 文件中的：

```
CONFIG_ESP32P4_SELECTS_REV_LESS_V3=y
```

编译 **v3.x** 版本固件时，P4 代码根目录下的 sdkconfig 文件中的：

```
CONFIG_ESP32P4_SELECTS_REV_LESS_V3=n
```

修改上述配置后，进行编译，最终自动生成的  sdkconfig 文件，还会有其它相关联的配置项会自动同步产生差别。

## 20260716

提升 OHOS_UART_RX_TASK_PRIO 任务的优先级到17（高于检测VAD信号的任务优先级18，也高于上传opus音频数据给WS63的任务优先级18），确保WS63下发的命令和Opus音频数据帧能够在第一时间得到处理，确保P4的音频缓冲区不至于溢出而丢失语音帧；

同时将 UART_RX_TASK 中的 uart_read_bytes 操作改为非阻塞式读取，确保每次Rx读取不到命令/数据的时候，立即释放CPU给其它任务（检测VAD信号的任务、上传opus音频数据的任务以及其它任务）进行调度和运行。

本次更改，有效提升了P4播放【云端下发到WS63再转发给P4的语音数据】的响应时间，以及播放语音数据的流畅性，基本上避免出现声音的丢失和卡顿现象。
